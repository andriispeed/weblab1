## Що працює

| Маршрут | Можливості |
|---|---|
| `/` | Головна, концепція школи, картки курсів із бази |
| `/courses` | Пошук за назвою/технологією, фільтри, сортування ціни |
| `/courses/:id` | Frontend / Python / QA, програма, ціна, FAQ, вибір курсу |
| `/contact` | Reactive Form, перевірка полів, згода, запис у PostgreSQL, номер заявки |
| `/admin` | Вхід, пошук і статуси заявок, видалення, редагування ціни/опису, історія дій |
| `/design` | Початковий дизайн, повна вимога та компроміс CR15 |

Заявки справді зберігаються на сервері та доступні команді після входу. Повторне надсилання одного запиту не створює дубліката. У публічному API немає списку заявок. Навчальний проєкт не приймає оплату й не надсилає автоматичних листів; для демонстрації варто використовувати вигадані дані.

## Структура

```text
Ind/
  design/                 # Figma-плагіни, перегляд макетів, tokens.json
  frontend/               # Angular 20.3: standalone components, Router, Reactive Forms
  backend/                # NestJS, параметризовані SQL-запити, міграції PostgreSQL
  infra/                  # Docker Compose, Nginx, deployment, backup
  scripts/                # дизайн-токени, пакування, публікація, E2E
  docs/                   # архітектура, CR15, виступ, перевірки
  legacy/static/          # збережена попередня HTML/CSS/JS-версія
  .private/               # локальні доступи та резервні копії — НЕ у Git
```

Кольори для Angular і Figma беруться з `design/tokens.json`. Команда `npm run tokens` генерує SCSS-змінні та типізований файл токенів для плагіна. Градієнт — CSS-оформлення; Angular відповідає за компоненти, маршрути та дані.

## Запуск локально

Потрібні Node.js 24, npm і PostgreSQL 17 (або Docker для бази).

1. У `Ind` виконай `npm ci` та `npm run tokens`.
2. Створи локальну базу та користувача PostgreSQL. Скопіюй `backend/.env.example` у `backend/.env`, заповни доступи та початковий пароль адміністратора (щонайменше 16 символів).
3. `npm run build --workspace backend`, потім `npm run start:api`.
4. В іншому терміналі: `npm start`.
5. Відкрий **http://localhost:4200/it-school/**. Для локального HTTP в `.env` використовуй `COOKIE_SECURE=false` і `PUBLIC_URL=http://localhost:4200/it-school/`.

Міграції запускаються при старті API в транзакції. Початкові три курси й обліковий запис адміністратора створюються один раз; наступний запуск не перезаписує дані.

## Production

Nginx обслуговує Angular за шляхом `/it-school/`, а `/it-school/api/` передає до API на `127.0.0.1:3100`. PostgreSQL не має опублікованого порту. Чинний застосунок за кореневою адресою збережено.

API та PostgreSQL працюють у Docker Compose із перевірками здоров’я, автоперезапуском, лімітами пам’яті та ротацією логів. Дані зберігаються в окремому Docker volume. Збірка TypeScript/Angular виконується локально або в CI; сервер отримує готові файли та встановлює лише runtime-залежності API.

Сесії адміністратора зберігаються в БД. Cookie має HttpOnly, Secure, SameSite=Strict та шлях `/it-school/`. Зміни потребують CSRF-токена; перевіряються Origin, поля запитів і частота надсилання. Пароль зберігається у вигляді scrypt-хешу.

Логін і випадковий пароль збережені **локально в `.private/admin-access.json`**, а на сервері — в `/opt/it-school/admin-access.json` із доступом лише root. Файли секретів не публікуються. Початковий пароль у змінних оточення використовується лише при створенні першого адміністратора.

### Оновлення

```powershell
cd C:\5sem\web\Ind
npm ci
npm run build
npm run package
.\scripts\deploy.ps1 -SshKey '<шлях до власного SSH-ключа>'
```

Скрипт пакує лише потрібні артефакти, створює окремий release, робить backup БД, перевіряє API та Nginx, перемикає `current`. Якщо перевірка не проходить, повертає попередні код і конфігурацію. Дані й міграції автоматично назад не відкочуються: відновлення БД — окрема явна операція.

[Експлуатація та резервні копії](docs/OPERATIONS.md). GitHub Actions збирає сайт/API, перевіряє production-залежності, запускає інтеграційний тест з окремим PostgreSQL і перевіряє типи Figma-плагіна. Автоматичний deploy із GitHub не вмикався: SSH-ключ не передавався GitHub.

## Перевірки

```powershell
npm run build
npm audit --omit=dev
npm run verify
```

Остання команда перевіряє публічний сайт, використовує приватний локальний доступ, створює лише позначені тестові заявки та прибирає їх. Тимчасова зміна ціни відновлюється. Запускати в погоджене вікно перевірки, оскільки це інтеграційний тест реального сервера.

[Опис перевірок і межі висновків](docs/TESTING.md).
