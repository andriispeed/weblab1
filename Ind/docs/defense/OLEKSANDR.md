## Твоя роль і межі роботи

Твоя частина — структура публічного Angular-застосунку: головна, каталог, детальна сторінка курсу, маршрути, повторно використовувані компоненти й навігація. Ти показуєш шлях «знайшов курс → прочитав програму → перейшов до запису».

Нижче — закріплені за тобою файли та частини реалізації. Для спільних файлів це розподіл відповідальності, а не твердження про одноосібне авторство. HTTP-сервіс, API, логін і адмінпанель пояснює Андрій; адаптивні стилі — Дар’я; поведінку форми — Арсеній.

## Як запускається застосунок

У `main.ts` виклик `bootstrapApplication(App, …)` створює кореневий компонент. Компоненти самостійні: потрібні залежності вказані в їхньому `imports`, окремого `AppModule` на фронтенді немає.

- `provideRouter(routes, …)` підключає маршрути. `scrollPositionRestoration: "enabled"` керує відновленням прокручування при навігації.
- `provideHttpClient(withInterceptors([securityInterceptor]))` робить HTTP-клієнт доступним через dependency injection; логіку interceptor розробляє напрям Андрія.
- `registerLocaleData(uk)` і `LOCALE_ID: "uk-UA"` дозволяють `DecimalPipe` та `DatePipe` використовувати українську локаль.
- `provideZonelessChangeDetection()` налаштовує оновлення інтерфейсу без Zone.js. У цьому проєкті стани сторінок переважно зберігаються у signals.

**Простими словами:** стартовий файл підключає можливості застосунку; компоненти описують конкретні екрани.

## Маршрути й оболонка

У `routes.ts`: `""` → головна, `courses` → каталог, `courses/:id` → курс, `contact` → форма. Додатково є `design`, `admin/login`, захищений `admin` і останній маршрут `**` для невідомих адрес.

`loadComponent: () => import(...).then(...)` — динамічний імпорт компонента. Код сторінки завантажується при переході на неї. `:id` — змінна частина адреси, наприклад `python`. `**` стоїть останнім, щоб не перехоплювати відомі маршрути.

`router-outlet` у `app.html` — місце, де Angular показує поточну сторінку. Шапка й футер залишаються спільними. `routerLink` запускає навігацію Angular; `routerLinkActive` та `ariaCurrentWhenActive` позначають поточний розділ.

| Частина `App` | Що робить | Для чого |
|---|---|---|
| `menu = signal(false)` | Зберігає, відкрите меню чи ні; у шаблоні читається як `menu()`. | Кнопка, видимість меню й `aria-expanded` мають спільний стан. |
| `constructor()` | Слухає `NavigationEnd`, закриває меню; після першої навігації переводить фокус на `main`. | Після вибору пункту користувач потрапляє до нового вмісту. |
| `takeUntilDestroyed()` | Завершує підписку при знищенні компонента. | Не залишати активного слухача після завершення його життєвого циклу. |
| `skipToMain(event)` | Скасовує стандартну дію посилання, фокусує `main`, прокручує до нього. | Клавіатурою можна пропустити повторювану навігацію. |
| `closeMenu(event)` | Якщо меню відкрите, закриває його й повертає фокус на кнопку. | Очікувана поведінка клавіші Escape. |

## Каталог: кожна функція та стан

`signal` — значення, зміни якого відстежує Angular. Читання: `query()`. Запис: `query.set("Python")`. `computed` — значення, обчислене з інших signals; його не потрібно вручну перераховувати в кожному обробнику.

| Назва в `CoursesPage` | Пояснення |
|---|---|
| `courses` | Початковий масив курсів, отриманий від сервера. |
| `loading`, `error` | Чи триває запит і який текст помилки показати. |
| `query` | Текст пошуку. |
| `category` | `all`, `dev` або `qa`. |
| `sort` | `default`, `price-asc` або `price-desc`. |
| `constructor()` | Викликає `load()` при створенні сторінки. |
| `load()` | Вмикає завантаження, очищує помилку, підписується на `api.courses()`. У `next` зберігає дані, в `error` показує повідомлення; обидві гілки завершують завантаження. |
| `filtered = computed(...)` | Поєднує категорію, пошук і сортування в один результат для шаблону. |
| `reset()` | Очищує пошук, повертає `all` і стандартний порядок. |

Алгоритм `filtered` по кроках:

1. `trim()` прибирає пробіли на краях запиту; `toLocaleLowerCase("uk")` зводить регістр.
2. `.filter()` залишає курси обраної категорії, у яких рядок із `title` та `tools` містить запит.
3. `.sort()` впорядковує результат за ціною або `position`. Метод змінює масив, але тут це **новий масив після filter**, а не вихідний `courses()`.
4. Шаблон перебирає `filtered()` через `@for`; `track course.id` допомагає Angular співставляти картки з конкретними курсами.

**Приклад:** `SQL` знаходить курси, у переліку інструментів яких є SQL; категорія «Тестування» додатково залишає лише QA. Новий HTTP-запит на кожну літеру не виконується — каталог малий, фільтрація локальна.

У шаблоні `[ngModel]="query()"` передає значення в поле, а `(ngModelChange)="query.set($event)"` повертає введений текст у signal. `@if` показує завантаження, помилку або результати. Якщо результатів немає, з’являється кнопка `reset()`.

## Головна, картка та деталі курсу

`HomePage.load()` працює за тією самою схемою завантаження, що й каталог. Це окремий стан сторінки, а не глобальний кеш. Повторний перехід може спричинити нове отримання даних.

У `CourseCard` поле `course = input.required<Course>()` означає обов’язковий вхідний об’єкт. Батько передає `[course]="course"`, картка читає `course()`. Вона **сама не робить HTTP-запиту**. `DecimalPipe` форматує ціну, а `[routerLink]="['/courses', course().id]"` відкриває відповідний курс.

У `CoursePage` немає окремого методу `load()`: логіка міститься в конструкторі та RxJS-ланцюжку:

1. `ActivatedRoute.paramMap` повідомляє про параметри маршруту.
2. `switchMap` бере `id` та підписується на `api.course(id)`; при зміні `id` відписується від попереднього внутрішнього запиту.
3. `catchError` всередині `switchMap` записує помилку й повертає `of(null)`, щоб зовнішній потік параметрів міг працювати далі.
4. `subscribe` записує курс, вимикає `loading` та через `Title.setTitle()` змінює назву вкладки.
5. `takeUntilDestroyed()` завершує підписку разом із компонентом.

`course.html` перебирає `modules`, показує ціну та програму. Кнопка запису додає `[queryParams]="{course:c.id}"`, тому адреса стає `/contact?course=python`. Це передає вибір формі Арсенія; заповнення заявки тут ще не відбувається.

## Питання викладача

- **Чому Angular?** Компоненти, маршрути, DI, форми й HTTP дозволяють послідовно організувати сайт; це також технологія нашого курсу.
- **Signal і computed — це одне?** Signal зберігає стан; computed виводить значення з інших signals.
- **Для чого subscribe?** HTTP-метод повертає Observable; підписка запускає виконання запиту й обробляє його результат або помилку.
- **Чому не фільтруєте каталог на сервері?** Зараз три курси. Для великого каталогу потрібні серверні пошук, сортування й пагінація.
- **Чи фільтри залишаються в URL?** Ні, у поточній реалізації це локальні стани сторінки. URL містить id детального курсу та вибір курсу при переході у форму.
- **Що, якщо курс не існує?** API повертає помилку, компонент показує її та посилання до каталогу. Невідомий загальний маршрут обробляє `**`.
- **Чи потрібне перезавантаження всього сайту?** Для звичайного `routerLink` — ні, Angular змінює компонент маршруту. Пряме відкриття URL підтримує серверний SPA fallback, який налаштовує Андрій.
- **Чому не використовували окремий HTML для кожного курсу?** Один компонент відображає різні об’єкти за id; виправлення шаблону працює для всіх курсів.
