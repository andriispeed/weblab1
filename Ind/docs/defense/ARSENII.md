# Арсеній Липський — форма запису та клієнтська валідація

Твій виступ: **4:00–6:00**, після Дар’ї. Ти створюєш демонстраційну заявку й передаєш слово Андрію, який знаходить її в адмінпанелі. Ця пам’ятка містить увесь матеріал твоєї частини.

[Форма для Python](https://telegrambot.vps.webdock.cloud/it-school/contact?course=python) · [Спільний сценарій](../DEFENSE.md)

## Твоя роль

Ти відповідаєш за користувацьку форму запису: поля, перевірку введення, згоду, підказки, фокус на помилці, блокування повторного натискання й відображення підтвердження. Твоє завдання — зробити так, щоб користувач розумів, що ввести, що виправити й чи була заявка прийнята.

**Бекенд, серверна валідація, HTTP-сервіс, авторизація та вся адмінпанель залишаються за Андрієм.** Файл `contact.ts` спільний: ти пояснюєш форму та стани інтерфейсу, Андрій — API-виклик, `requestId` і серверну обробку. Це карта відповідальності за реалізацію; спільний файл не приписується одному автору цілком.

## Як побудована форма

`ReactiveFormsModule` дозволяє описати модель форми в TypeScript і зв’язати її з HTML. `FormBuilder.nonNullable.group(...)` створює групу контролів: значення мають конкретні типи, а після `reset()` повертаються до початкових значень замість `null`.

| Поле | Початкове значення | Правила та призначення |
|---|---|---|
| `name` | Порожній рядок | Обов’язкове, 2–80 символів. Pattern `/\S.{0,78}\S/` вимагає непробільні перший і останній символи. Перед надсиланням краї обрізаються через `trim()`. Це не перевірка «лише літери»: пробіли всередині імені допустимі. |
| `email` | Порожній рядок | Обов’язкове, `Validators.email`, максимум 160 символів. Перевіряє формат, а не існування скриньки. |
| `course` | `consultation` | Напрям або консультація. Обраний курс може прийти з URL. Сервер окремо обмежує дозволені значення. |
| `message` | Порожній рядок | Необов’язковий текст до 1000 символів. |
| `consent` | `false` | `Validators.requiredTrue`: checkbox має бути саме ввімкнений. |

`[formGroup]="form"` підключає всю модель до `<form>`, `formControlName="email"` підключає конкретний input. `(ngSubmit)="submit()"` викликає обробник. `novalidate` вимикає стандартні браузерні діалоги валідації, щоб форма показувала свої повідомлення; Angular-валідатори при цьому працюють.

## Стани компонента

| Змінна | Що означає |
|---|---|
| `courses` | Варіанти курсу для select. |
| `courseError` | Не вдалося отримати каталог. Окремо від помилки надсилання. |
| `error` | Загальна помилка форми або API, показана через `role="alert"`. |
| `saving` | Триває надсилання: кнопка заблокована, напис «Надсилаємо…». |
| `receipt` | `null` до успіху; після успіху — об’єкт із номером, датою та статусом відповіді. |
| `submitted` | Чи була спроба надсилання; дозволяє показати помилки ще не торкнутих полів. |
| `requestId` | UUID поточної спроби заявки. Передається серверу для захисту від дублювання; API-частина Андрія. |

Signals читаються як функції, наприклад `saving()`, а змінюються через `.set(...)`. `submitted` — звичайний boolean, який змінюється в обробниках подій форми.

## Кожен метод ContactPage

### `constructor()` — початкове налаштування

Читає `course` через `ActivatedRoute.snapshot.queryParamMap`. Якщо це `frontend`, `python` або `qa`, встановлює курс у контролі. Інше значення ігнорується, лишається консультація. Потім викликає `loadCourses()`.

Це **одноразове читання snapshot при створенні компонента**, а не підписка на будь-яку подальшу зміну query-параметрів. Для нашого переходу зі сторінки курсу цього достатньо.

### `loadCourses()` — наповнити select

Очищує `courseError`, отримує курси через готовий сервіс Андрія й записує результат у `courses`. При помилці показує пояснення та кнопку повторного завантаження. Опція «Допоможіть обрати курс» є в HTML незалежно від відповіді API. Якщо обраний напрям не завантажився, користувач може явно обрати консультацію; автоматичного переведення будь-якого попереднього вибору немає.

### `invalid(name)` — вирішити, чи показувати помилку

Приймає ім’я контролу: `name`, `email` або `consent`. Повертає `c.invalid && (c.touched || this.submitted)`.

`invalid` означає, що порушене правило; `touched` — поле вже відвідали й залишили. Отже, порожню нову форму не заповнюють повідомленнями одразу. Після спроби надсилання помилки з’являються також у полях, до яких ще не переходили.

### `submit()` — перевірити й надіслати

1. Якщо `saving()` уже істинне, негайно повертається: другий клік не створює паралельний запит із цієї форми.
2. Ставить `submitted = true`, прибирає попередню загальну помилку.
3. Через `patchValue()` замінює ім’я та email їхніми значеннями без крайніх пробілів. Інші поля не скидаються.
4. Якщо форма некоректна, викликає `markAllAsTouched()`, встановлює загальне пояснення та після оновлення DOM фокусує перший елемент із `aria-invalid="true"`. HTTP-запиту в цій гілці немає.
5. Якщо форма коректна, ставить `saving = true`. API-частина передає `getRawValue()` разом із `requestId` через `api.apply(...)`.
6. У `next` записує серверну квитанцію в `receipt`, вимикає `saving` і переводить фокус на блок підтвердження.
7. В `error` вимикає `saving` і показує повідомлення через `errorMessage`. Введені дані залишаються у формі; хибного успіху немає.

`requestAnimationFrame()` тут дає браузеру можливість застосувати новий стан шаблону перед пошуком елемента для фокусу. `getRawValue()` отримує об’єкт значень усіх контролів. Зараз у цій формі поля не вимикаються, блокується лише кнопка.

### `another()` — почати іншу заявку

Прибирає квитанцію, викликає `form.reset()`, створює **новий** `requestId`, скидає `submitted` та `error`, фокусує ім’я. Після reset напрям стає `consultation`, згода — `false`; Python із початкового URL повторно не підставляється, бо конструктор не викликається ще раз.

## HTML і доступність

- `label for="student-email"` пов’язаний із `input id="student-email"`: мітка залишається видимою після введення.
- `aria-invalid` повідомляє стан поля, `aria-describedby` пов’язує його з текстом помилки.
- `role="alert"` позначає повідомлення про помилку, `role="status"` — успішне збереження.
- `[attr.aria-busy]="saving()"` повідомляє, що форма зайнята; `[disabled]="saving()"` блокує кнопку.
- `@if(receipt(); as r)` перемикає форму на квитанцію. `DatePipe` форматує `createdAt`.
- `tabindex="-1"` дозволяє програмно сфокусувати квитанцію, не додаючи її до звичайної послідовності Tab.

## Запитання викладача

- **Навіщо валідація ще й на сервері?** JavaScript можна обійти прямим HTTP-запитом. Фронтенд забезпечує зручність; сервер контролює прийнятні дані.
- **required і requiredTrue — різниця?** Для імені потрібне непорожнє значення; для згоди потрібне саме boolean `true`.
- **Перевірка email доводить, що адреса існує?** Ні, лише відповідність формату. Підтвердження адреси листом не реалізоване.
- **Чи достатньо disabled для захисту від дублювання?** Ні. Тут це захист від повторного кліку, а сервер використовує унікальний `requestId`.
- **Що, якщо відповідь сервера загубилася?** Форма показує помилку. Повтор того самого запиту використовує той самий `requestId`; деталі серверної ідемпотентності пояснює Андрій.
- **Де зберігаються дані до надсилання?** У стані Angular-форми в браузері. Автозбереження чернетки в localStorage немає; перезавантаження може стерти введене.
- **Навіщо patchValue, а не reset?** Треба прибрати пробіли лише у двох полях, зберігши курс, повідомлення та згоду.
- **Чому квитанція не з’являється одразу після кліку?** Успіх визначає серверна відповідь `next`, а не сам факт натискання.

## Що повторити самостійно

Знайди всі п’ять методів: `constructor`, `loadCourses`, `invalid`, `submit`, `another`. Поясни кожну гілку `submit`. Перевір порожню форму, email `abc`, відсутню згоду та одну успішну демонстраційну заявку. Повний `verify-live.mjs` змінює серверні тестові дані й перевіряє також адмінпанель — не запускай його лише для читання своєї частини.
