Твоя зона — SCSS/CSS, кольори, типографіка, відступи, сітки, кнопки, поля, адаптивна навігація, футер і компроміс щодо вимоги градієнтного тексту. Треба пояснити, чому одна HTML-структура працює на Desktop, Tablet і Mobile, та показати код, який це забезпечує.

Файли нижче визначають закріплені частини реалізації. У спільних файлах це не одноосібне авторство: Олександр керує логікою навігації, Арсеній — поведінкою форми, Андрій — адмінпанеллю та API. Ти оформлюєш їхні елементи й стани.

## Як організовані стилі

У `styles.scss` є підключення `@use "styles/tokens"`. Файл `_tokens.scss` визначає змінні в `:root`, тому вони доступні всьому документу. Наприклад, `--primary: #7A5C00`, `--paper: #FAF9F6`, `--ink: #22231F`.

`var(--primary)` підставляє значення CSS-змінної. Це дозволяє використовувати один узгоджений колір у кнопках, фокусі та акцентах. SCSS — формат вихідного файла, який збірка перетворює на CSS; `--primary` є саме змінною CSS, а не Sass-змінною `$primary`.

Команда з папки `Ind/`: `npm run tokens`. Вона читає `design/tokens.json` і генерує кольори, темну палітру градієнта, запасний колір і радіус. **Не всі поля JSON переносяться до SCSS:** медіазапити 640/1000 px і частина типографіки записані у `styles.scss`; зміна `breakpoints` у JSON сама їх не змінить. Скрипт також оновлює локальні матеріали Figma, але їх не треба показувати як твою роль.

## Grid, Flexbox і медіазапити

Фрагмент, який варто відкрити на захисті:

```css
.courses-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 24px;
}
@media (max-width: 1000px) {
  .courses-grid { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
@media (max-width: 640px) {
  .courses-grid { grid-template-columns: 1fr; }
}
```

Це зведений фрагмент чинних правил; у файлі мобільне правило об’єднане з іншими селекторами.

`repeat(3, ...)` створює три колонки. `1fr` — частка доступної ширини. `minmax(0, 1fr)` дозволяє колонці стискатися нижче автоматичного мінімуму, який інакше може задавати довгий вміст. `gap` створює проміжки між елементами. Grid зручний для сітки карток, Flexbox — для розташування елементів уздовж одного напрямку та вирівнювання.

| Ширина | Каталог | Інші зміни |
|---|---|---|
| 1440 px | 3 колонки | Широкий контейнер і горизонтальна навігація. |
| 768 px | 2 колонки | Основні двоколонкові вступи та контактна секція перебудовуються. |
| 390 px | 1 колонка | Компактне меню, менші відступи, кнопки й поля під ширину блока. |
| 320 px | 1 колонка | Додаткові правила до 360 px зменшують великі заголовки й padding. |

Є також допоміжний поріг 1100 px для проміжних розмірів. Адаптивність не зроблена приховуванням переповнення через `overflow-x: hidden`: треба, щоб вміст справді поміщався й залишався доступним.

## Градієнт: пояснення кожної частини

У продакшн-інтерфейсі клас `.gradient-heading` застосовано до великих заголовків і назв курсів. Основна палітра: **#7A5C00 → #4F356E → #245F57**.

```css
background-image: linear-gradient(
  90deg,
  var(--gradient-1) 0%,
  var(--gradient-2) 50%,
  var(--gradient-3) 100%
);
background-clip: text;
-webkit-background-clip: text;
color: transparent;
-webkit-text-fill-color: transparent;
```

- `linear-gradient` — CSS-функція, яка створює зображення плавного переходу; це не Angular-функція.
- `90deg` спрямовує градієнт зліва направо; три позиції задають початок, середину та кінець.
- `background-clip: text` залишає фон видимим лише всередині літер.
- Прозора заливка дозволяє побачити цей фон замість суцільного кольору тексту.
- `width: fit-content` обмежує ширину блока вмістом, `max-width: 100%` не дозволяє заголовку виходити за контейнер.
- `@supports` застосовує ефект лише за підтримки потрібної можливості; інакше залишається успадкований суцільний текст. `background-color: var(--gradient-fallback)` задає резервну заливку під градієнтом.
- Другий `@supports` використовує `90deg in srgb`, якщо браузер підтримує явне зазначення простору інтерполяції. Розрахунки палітри в документації зроблено для sRGB.

У `DesignPage` є **один стан `mode = signal("headings")`**, окремих методів перемикання немає. Кнопки викликають `mode.set('original' | 'full' | 'headings')`. Шаблон додає `.gradient-full` або `.gradient-titles`; CSS у першому випадку оформлює `h2`, `p`, `strong`, у другому — лише `h2`. Це демонстрація фрагмента сторінки, а не перемикач оформлення всього сайту.

## Резервні режими та шрифт

`@media (forced-colors: active)` повертає системний суцільний `CanvasText`, щоб примусова палітра користувача не залишила прозорий текст. `@media print` прибирає градієнт і непотрібну навігацію. `prefers-reduced-motion` вимикає переходи кнопок. Сам градієнт статичний, анімації в ньому немає.

`@font-face` завантажує локальний `InterVariable.woff2`, діапазон ваг 100–900. `font-display: swap` дозволяє спочатку показати запасний шрифт. Типографіка також використовує `clamp`, наприклад для h1: мінімум, бажаний розмір від ширини вікна та максимум. Частину розмірів уточнюють медіазапити.

## Як аргументувати компроміс CR15

Замовник попросив весь основний текст зробити триколірним. Команда **частково врахувала** вимогу: залишила ефект у заголовках, а абзаци, ціни, навігацію й поля — однотонними. Причина — візуальна ієрархія та відповідність функціоналізму, а не технічна неможливість повної реалізації.

Для звичайного тексту WCAG 2.1, критерій 1.4.3, задає мінімум 4.5:1, для великого — 3:1. Сам градієнт не заборонений: оцінюють контраст тексту з фоном. [Офіційне пояснення W3C](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html).

У нашому [розрахунку палітри](../CHANGE_REQUEST.md) мінімум на білому фоні — 6.25:1, на `#FAF9F6` — 5.94:1, на `#FFF8E6` — 5.90:1. Це розрахунок 1001 позиції на кожному з двох відрізків sRGB-градієнта, а не повний аудит сайту. Темна палітра могла б застосовуватися і до абзаців; ми обрали стриманіше оформлення за концепцією.

Критерій Reflow стосується, зокрема, перебудови вертикального вмісту на ширині 320 CSS px без необхідності прокручувати у двох напрямках, з винятками для вмісту, якому потрібна двовимірна структура. Окрема перевірка вузького екрана не доводить повну відповідність усім WCAG. [W3C: Reflow](https://www.w3.org/WAI/WCAG21/Understanding/reflow.html).

Про Core Web Vitals: ефект не потребує окремої картинки чи мережевого запиту, але це **не вимірювання** LCP, INP або CLS. Не стверджуй, що градієнт сам по собі погіршує швидкість або що команда довела вплив на конверсію.

## Текст виступу

> Моя зона відповідальності — адаптивна верстка, CSS і градієнти. Ми використали єдину структуру сторінок, яка перебудовується під ширину екрана. Зараз каталог має три колонки на комп’ютері. На планшетній ширині залишається дві, а на телефоні — одна. Меню стає компактним, відступи зменшуються, але всі основні дії залишаються доступними.
>
> У styles.scss це реалізовано через CSS Grid і медіазапити. Для колонок використано minmax із нульовим мінімумом, щоб довгий вміст не розтягував сітку. Flexbox допомагає вирівнювати елементи навігації та карток. Кольори винесено у CSS-змінні: базовий #7A5C00 використовується послідовно в різних компонентах.
>
> Додаткова вимога замовника — залити весь основний текст триколірним градієнтом. Ми обрали часткове врахування. На сторінці порівняння можна побачити повну вимогу й наш компроміс: градієнтні заголовки, однотонні абзаци та службовий текст. Це зберігає ієрархію функціоналістичного інтерфейсу.
>
> Ефект створює linear-gradient, а background-clip обмежує його формою літер. Це звичайний CSS у нашому Angular-застосунку. Для друку й режиму примусових кольорів передбачено суцільну заливку. Наша палітра має розрахований контраст понад п’ять цілих дев’ять десятих до одного на використаних світлих фонах. Сам градієнт не порушує WCAG автоматично, а розрахунок кольорів не замінює повний аудит доступності.
>
> Тепер Арсеній покаже, як користувач взаємодіє з формою запису.

## Питання викладача

- **Градієнт робить Angular?** Ні, браузер відображає CSS; Angular керує станом перемикача в демонстрації.
- **Чому не градієнт у всіх абзацах?** Компроміс зберігає акценти й ієрархію; це вибір концепції, а не заборона стандарту.
- **Що таке breakpoint?** Ширина, за якої застосовується медіазапит і змінюється компонування.
- **Чому 3 → 2 → 1?** Так картки мають достатню ширину для назви, опису й дії на відповідних екранах.
- **Чи достатньо overflow-x: hidden?** Ні: він може приховати потрібний вміст. Треба виправляти розміри й перенос рядків.
- **Навіщо CSS-змінні?** Єдині значення для спільних елементів; менше випадкових розбіжностей.
- **Що станеться без підтримки text clipping?** Основний `.gradient-heading` має перевірку підтримки, тому залишається читабельний суцільний текст.
- **Чи є виміряні Core Web Vitals?** У межах цієї аргументації немає польового звіту; описуємо реалізацію й перевірені сценарії, не вигадуємо оцінку.

Перед захистом повтори `minmax`, `1fr`, `@media`, `@supports`, `var`, `background-clip` та логіку `mode`. Відкрий потрібні місця коду завчасно, щоб не шукати їх у великому SCSS-файлі під час виступу.
