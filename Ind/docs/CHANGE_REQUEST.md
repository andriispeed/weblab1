# CR15 — триколірний градієнт основного тексту

**Вимога замовника:** «Один колір шрифту для тексту — це нудно. Зробіть так, щоб увесь основний текст на сторінках заливався трьохколірним лінійним градієнтом замість суцільного кольору».

**Рішення команди від 18.11.2026: часткове врахування, компромісний рефакторинг.** Лінійний градієнт із трьома кольорами застосовано до великих заголовків і назв курсів. Абзаци, програма курсу, ціни, інтерфейс форми та навігація зберігають суцільний колір.

## Навіщо обрано компроміс

Бажання замовника зробити сторінки виразнішими враховане в найпомітніших текстових елементах. Водночас основна задача відвідувача — читати програму, порівнювати курси та заповнювати заявку. Суцільний колір довгих текстів підтримує спокійну ієрархію функціоналістичного інтерфейсу. Градієнт не конкурує з кожним абзацом за увагу.

Це **дизайнерське рішення**, а не доведений експериментом ефект на конверсію. Тести з реальними користувачами не проводилися. Ми не стверджуємо, що будь-який градієнт погано читається або автоматично порушує WCAG.

## Контраст / WCAG 2.1

Критерій **1.4.3** вимагає щонайменше **4.5:1** для звичайного тексту та **3:1** для великого. Перевіряється контраст тексту щодо фону, а не сам факт наявності градієнта. [W3C: Contrast Minimum](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html).

Основна палітра: **#7A5C00 → #4F356E → #245F57**. Вона містить заданий гірчично-коричневий колір. Розрахунок проведений для sRGB-інтерполяції: 1001 позиція на кожному з двох відрізків. Числа нижче округлені для показу; перевірка порога використовує точні значення.

| Фон | Найнижчий розрахований контраст |
|---|---:|
| Білий `#FFFFFF` | 6.25:1 |
| Основний `#FAF9F6` | 5.94:1 |
| Акцентний `#FFF8E6` | 5.90:1 |
| Темний `#252A24`, світла палітра `#FFE3A3 → #E3D5FF → #B8E8DD` | 10.61:1 |

Отже, нашу темну палітру технічно можна використати і в основному тексті. Команда обрала заголовки через візуальну ієрархію та тематику проєкту. Це не аргумент про «заборонений стандартом градієнт». Розрахунок палітри не є повним аудитом відповідності сайту всім критеріям WCAG.

У CSS є суцільний резервний колір, перевірки `@supports`, видимий фокус, читабельне виділення тексту, а також суцільний текст для `forced-colors` і друку. Особливості `background-clip: text` та резервного оформлення описані в [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/background-clip).

## Адаптивність / Responsive Grid

Градієнт змінює заливку тексту, а не ширину сітки. Тому твердження «градієнт ламає адаптивність» було б некоректним. У сайті використані CSS Grid, Flexbox, `minmax(0, 1fr)` та перебудова карток **3 → 2 → 1**. Для Angular-версії перевіряються ширини 320, 390, 768, 1024 і 1440 px; окремо панель команди — 320, 390, 768 і 1440 px. Деталі — у [TESTING.md](TESTING.md).

Перевірка на 320 CSS px пов’язана з критерієм **1.4.10 Reflow**. Цього окремого тесту недостатньо, щоб оголосити повну відповідність WCAG. [W3C: Reflow](https://www.w3.org/WAI/WCAG21/Understanding/reflow.html).

## Продуктивність / Core Web Vitals

Оформлення реалізоване статичним CSS-градієнтом, без анімації, зображення тексту чи додаткового JavaScript для ефекту. Додаткових мережевих запитів для самого градієнта немає. Форма й навігація використовують звичайний текст у DOM.

Ми не стверджуємо, що повна реалізація погіршує Core Web Vitals, і не вигадуємо результати вимірювання. Орієнтири Google: **LCP ≤ 2.5 с, INP ≤ 200 мс, CLS ≤ 0.1**, оцінювані на 75-му перцентилі реальних відвідувань. Після публікації потрібні окремі вимірювання; локальна перевірка функціоналу не замінює ці дані. [Google: Web Vitals](https://web.dev/articles/vitals).
